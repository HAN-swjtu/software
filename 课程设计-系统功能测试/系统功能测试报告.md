## 二、实验前提与理论依据

### 2.1 黑盒测试（课件要点）

- **定义**：把程序看作黑盒，只根据需求规格检查输入/输出与界面行为，不关心内部实现（数据驱动测试）。  
- **常用方法**：等价类划分、边界值分析、判定表、因果图、场景法、Pairwise/正交试验等。  
- **设计流程**：模块划分 → 确定测试点 → 选方法设计用例 → 评审 → 执行 → 记录缺陷。

### 2.2 测试工具（课件要点）

- **JUnit 5**：`@Test`、`@BeforeEach`、`@AfterEach`、`Assert` 断言验证预期结果。  
- **Selenium WebDriver**：驱动浏览器模拟用户操作，适合 Web UI 回归测试。  
- **架构**：JUnit Platform + Jupiter；本实验在 Eclipse 或 Maven 命令行中执行 `mvn test`。

## 九、实验收获与体会

1. **等价类 + 边界值** 适合单字段输入（登录、搜索）；**判定表** 适合多条件业务（审批流）。  
2. 黑盒测试应结合**角色权限**（`main.js` 中 `ROLE_PERMISSIONS`），否则易漏测。  
3. **Selenium** 适合稳定 UI 回归；对弹窗表单、文件下载需额外处理，本实验以导航与登录为主。  
4. 前后端分离项目必须先**部署 API**，再测员工类账号；管理员 `root` 可作为环境自检账号。  
5. JUnit 5 的 `@BeforeEach` 管理 WebDriver 生命周期，避免浏览器进程残留。
